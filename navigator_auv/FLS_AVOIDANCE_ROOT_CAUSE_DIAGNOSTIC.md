### 1. Pipeline Data Flow (as designed)

### 3. The Problem

**velocity_cbf.py subscribes to SCG topics but does NOT use that data for CBF constraints.**

Instead, velocity_cbf.py only builds CBF constraints from:
1. PointCloud2 data (point_cloud_obstacles parameter)
2. Spatial memory (old detections)

The SCG data (obstacle_count, gap_width, etc.) is read but only **logged for diagnostics**, not used to generate constraints.

When PointCloud2 is not publishing → no constraints → `action=no_obstacle` → vehicle ignores obstacles.

### 4. Verification

From velocity_cbf.py line ~838-839:
```python
if self._point_cloud_is_fresh() and len(self.filtered_points):
    point_sets.append(np.asarray(self.filtered_points, dtype=float))
    source_parts.append('point_cloud')
```

No corresponding code path for SCG data:
```python
# MISSING: No integration of SCG gap/obstacle data into constraints
```

### 5. Root Cause

**velocity_cbf.py architecture mismatch:**
- Receives gap info from only_gap.py (via SCG topics)
- But doesn't use it to build CBF constraints
- Only waits for PointCloud2 data
- When PointCloud2 not publishing → zero constraints applied
- Result: Vehicle follows planner commands unfiltered

## Fix Required

Modify velocity_cbf.py to build CBF constraints from SCG data:
- Use `/rexrov2/scg/selected_gap_angle` and `/rexrov2/scg/selected_gap_width` to generate obstacle representations
- Or revert to using only SCG-based decisions instead of point cloud
